# 2027 program data schema

Last updated: August 2026 (planning)

This document defines the CSV schema for the **2027 annual refresh**. It replaces the free-text-heavy 2026 format with structured, one-row-per-offering data that supports accurate filtering and grouped search results.

**Related docs:** [DATA.md](./DATA.md) (2026 schema, pricing/flags decisions), [TASKLIST.md](../TASKLIST.md)

**Source file (planned):** `data/source/summer-programs-2027.csv`

**Current inventory:** [PROGRAM-CATALOG.md](./PROGRAM-CATALOG.md) — all 147 offerings tracked as of the 2026 baseline.

---

## Design principles

1. **One row = one searchable offering** — a specific combination of program family × track/session × format × date window × price. If a parent could ask "show me *this* in July under $5k," it gets its own row.

2. **Structured fields at source** — dates, grades, and prices are entered as structured values in the CSV. The import script validates and maps them; it does not guess from prose.

3. **No cross-references** — every row is self-contained. Forbidden values include "See pricing above," "Choose session," "Varies by track," and multi-session date strings in a single cell.

4. **`Program Group ID` for display only** — filtering runs on individual rows. Search results collapse rows that share a group ID into one tile (when 2+ variants match). See [Search result grouping](#search-result-grouping) below.

5. **Flags stay curated** — gotcha flags remain in `data/seed/flags.json`, keyed by `programGroupId` or name pattern. Not inline in the CSV.

6. **Rolling season updates** — rows move from `needs_review` → `awaiting_source` → `provisional` → `verified` at different times. **Season Year** and **Review Status** track progress; the site can show partial coverage honestly.

## Column reference

Columns are listed in recommended CSV order. **Required** columns must be non-empty on every row.

| # | Column | Required | Type | Notes |
|---|---|---|---|---|
| 1 | **Program Group ID** | Yes | slug | Stable identifier for the program family. Used for search-result grouping and flag matching. Lowercase, hyphenated (e.g. `harvard-pre-college`, `cosmos-uc-davis`). Must not change year over year unless the program genuinely splits or merges. |
| 2 | **Program Name** | Yes | string | Display name shown on cards (e.g. `Harvard Pre-College Program`, `COSMOS UC Davis`). |
| 3 | **Institution** | Yes | string | Host organization, distinct from program name (e.g. `Harvard University`, `UC Davis`). Used for name/institution search. |
| 4 | **Offering Label** | Yes | string | What makes *this row* distinct within the group: session name, track, course, or format variant (e.g. `Session II`, `Residential Session`, `Biotechnology & Cancer Biology`, `Commuter — Core Day`). Use `General` for programs with no meaningful sub-label. |
| 5 | **Primary Category** | Yes | enum | One of the [twelve categories](#primary-categories). Must match exactly. |
| 6 | **Secondary Tags** | No | csv | Comma-separated secondary categories from the same list. |
| 7 | **Format** | Yes | enum | Exactly one: `Residential`, `Commuter`, or `Online`. No slash-separated values. |
| 8 | **Grades Display** | Yes | string | Human-readable eligibility (e.g. `Rising 10–12`, `Completed grades 8–12, CA residents only`). Shown on cards. |
| 9 | **Grade Completed Min** | Yes | integer | Lowest grade *completed* (not rising). Range: 1–12. See [Grade rules](#grade-rules). |
| 10 | **Grade Completed Max** | Yes | integer | Highest grade completed. Range: 1–12. Must be ≥ min. |
| 11 | **Admission Type** | Yes | enum | One of: `First-Come`, `Application`, `Highly Competitive`. Import maps to normalized IDs. Additional deadline notes go in **Admission Display** (optional) or **Offering Label**. |
| 12 | **Length Display** | Yes | string | Human-readable duration (e.g. `2 weeks`, `4 weeks`, `1–4 weeks`). Shown on cards. |
| 13 | **Length Min Days** | No | integer | Inclusive minimum length in days. Required when length is known; leave empty only for genuinely variable/unknown durations. |
| 14 | **Length Max Days** | No | integer | Inclusive maximum length in days. Equal to min for fixed-length programs. |
| 15 | **Date Start** | Yes* | ISO date | `YYYY-MM-DD` inclusive start. *Required unless **Dates Parse Quality** is `unknown`. |
| 16 | **Date End** | Yes* | ISO date | `YYYY-MM-DD` inclusive end. *Same exception as Date Start. |
| 17 | **Dates Display** | No | string | Optional card override when ISO dates need context (e.g. `Jul 5–17, 2027`). Defaults to formatted Date Start – Date End at import if blank. |
| 18 | **Dates Parse Quality** | Yes | enum | `exact`, `approximate`, or `unknown`. Use `unknown` only for year-round/self-paced offerings with no meaningful summer window. |
| 19 | **Location Display** | Yes | string | Human-readable location (e.g. `Cambridge, MA`, `Online`, `British Virgin Islands`). |
| 20 | **State** | No | string | US state/territory code or full name when applicable (e.g. `MA`, `California`). Empty for online-only or international. Used for location filtering. |
| 21 | **Country** | Yes | string | ISO-style or full name (e.g. `US`, `United Kingdom`). Used for international detection. |
| 22 | **Credit Display** | Yes | string | Human-readable credit info (e.g. `No`, `Yes (3 college credits)`, `Certificate only`). |
| 23 | **Has College Credit** | Yes | boolean | `Yes` or `No`. |
| 24 | **Price Display** | Yes | string | Human-readable price for the card (e.g. `$6,100`, `$1,250/week`, `Free`, `Contact program`). |
| 25 | **Price Min** | No | number | Numeric minimum USD for this offering. `0` for free/fully funded. Empty when **Price Display** is `Contact program`. |
| 26 | **Price Max** | No | number | Numeric maximum USD. Equal to min for fixed prices. Empty when unknown. |
| 27 | **Fully Funded** | Yes | boolean | `Yes` or `No`. |
| 28 | **Financial Aid Available** | No | boolean | `Yes` or `No`. Default `No` at import if blank. |
| 29 | **URL** | Yes | url | Program or offering page. Must be a valid https URL. |
| 30 | **Description** | No | string | One sentence describing this specific offering. Improves text search; shown on expanded variant rows. |
| 31 | **Season Year** | Yes | integer | Which summer season this row describes (e.g. `2027`). Lets one file hold rows at different refresh stages during a rolling update. |
| 32 | **Review Status** | Yes | enum | Editorial workflow state for this row. See [Rolling refresh & review status](#rolling-refresh--review-status). |
| 33 | **Data Verified At** | No | ISO date | Date (`YYYY-MM-DD`) this row was last checked against a program source. Required when **Review Status** is `verified`. |
| 34 | **Review Notes** | No | string | Internal only — not published. e.g. `"Waiting on 2027 tuition PDF"`, `"Dates confirmed; price TBD"`. |

### Format values

Exactly one per row:

| CSV value | Normalized ID |
|---|---|
| `Residential` | `residential` |
| `Commuter` | `commuter` |
| `Online` | `online` |

Do not use `Both`, `Residential/Commuter`, `Varies`, or combined format strings. Split into separate rows.

### Admission type values

| CSV value | Normalized ID |
|---|---|
| `First-Come` | `first_come` |
| `Application` | `application` |
| `Highly Competitive` | `highly_competitive` |

Use the normalized label in the CSV where possible. Import may still accept legacy free-text strings during migration, but new rows should use these three values.

### Grade rules

- **Grade Completed Min/Max** are the filterable range. Enter the grade the student will have *finished* before the program starts.
- **Rising grade → completed grade:** rising 10th → min/max centered on 9; rising 11th → 10; etc.
- **Age-based eligibility:** convert to the best-fit completed-grade range and set **Grades Display** to show the original age language (e.g. `Ages 15–17 (rising Jr/Sr)` with min `10`, max `11`).
- State or residency restrictions (e.g. CA residents only) belong in **Grades Display** and/or flags — not in grade min/max alone.

### Price rules

- **Every row carries its own price.** Never reference another row.
- **Price Min/Max** are total program cost in USD for *this offering* (not application fees unless noted in display).
- **`Contact program`:** set **Price Display** to `Contact program`; leave **Price Min/Max** empty. Search behavior unchanged from 2026 — included in price filters by default.
- **`Free` / fully funded:** **Price Min** and **Price Max** = `0`; **Fully Funded** = `Yes`.
- **Per-week pricing:** enter the weekly rate in both min and max if fixed (e.g. `$1,250/week` → min `1250`, max `1250`); note `/week` in **Price Display**.

### Date rules

- **One date window per row.** Multi-session programs → one row per session (see examples).
- **Date Start/End** use the program's actual calendar year (2027 for summer 2027).
- **Dates Parse Quality:**
  - `exact` — both dates are confirmed
  - `approximate` — month-level estimate (e.g. only month known); use best-effort start/end
  - `unknown` — no meaningful date window (self-paced, year-round); leave Date Start/End empty
- Do not put semicolon-separated session lists in any date field.

## Rolling refresh & review status

Program data for a new season is updated **on a rolling basis** — some hosts publish dates in September, others not until January or later. The schema supports a single CSV (and one published dataset) while rows move through review at different times.

### Season Year

- Every row must declare **Season Year** (e.g. `2027`).
- During migration, rows still showing 2026 data should use **Review Status** `provisional` or `awaiting_source`, not a mismatched season year.
- Once 2027 dates/prices are confirmed, set **Season Year** to `2027` and update **Review Status** accordingly.
- Import validates that **Date Start/End** fall in a sensible window for the declared season (roughly calendar year `Season Year − 1` through `Season Year` for northern-hemisphere summer).

### Review Status values

| Status | Meaning | Publish to site? | User-facing signal |
|---|---|---|---|
| `verified` | Checked against a 2027 (or target season) program source; **Data Verified At** set | Yes | None — treat as current |
| `provisional` | Published for planning, but some fields may be prior-season or estimated | Yes | Badge: **"2027 details not yet confirmed"** on card; optional tooltip: "Verify dates and cost on program site" |
| `awaiting_source` | Program has not released target-season info; row kept for continuity | Optional* | Badge: **"Awaiting 2027 announcement"**; strongly encourage verifying on program site |
| `needs_review` | Internal queue — not ready for parents | No** | — |

\* **Policy choice:** either hide `awaiting_source` rows from search until at least `provisional`, or show them with a prominent disclaimer so families know the listing may be stale. Recommend **show with badge** for programs families expect (Harvard, COSMOS) so they aren't missing from search; hide only if the entire offering is discontinued.

\** Rows with `needs_review` are excluded from `programs.json` at import until status changes.

### Internal tracking (CSV / Sheets)

Use **Review Status** + **Review Notes** + **Data Verified At** to drive editorial workflow:

- Filter Sheets by `needs_review` or `awaiting_source` to see backlog.
- Dashboard script (planned): `% verified`, `% provisional`, count `awaiting_source` by **Program Group ID**.
- When a whole group is verified, all rows in that group should reach `verified` together (avoid mixed status on collapsed group cards when possible).

### Website display (planned)

| Surface | Behavior |
|---|---|
| **Search / program cards** | Show badge when `reviewStatus` is `provisional` or `awaiting_source` |
| **Expanded variant rows** | Same badge per variant if statuses differ within a group |
| **Search page header** | Rolling message when any published row is not `verified`, e.g. "147 programs · 89 verified for 2027 · others awaiting host updates" |
| **Site-wide footer / data line** | Keep envelope `verifiedAt` as *last import date*; add "season coverage" summary when partial |
| **Review Notes** | Never shown to users |

### Normalized seed fields

Import maps CSV columns to Program record:

- `seasonYear: number`
- `reviewStatus: "verified" | "provisional" | "awaiting_source"` (only published statuses)
- `dataVerifiedAt: string | null`
- `reviewNotes` is **not** imported into seed JSON (CSV-only)

## Program Group ID rules

`Program Group ID` identifies a **program family**, not a name string.

| Rule | Example |
|---|---|
| Same family, same group | All Harvard Pre-College sessions → `harvard-pre-college` |
| Different campuses → different groups | `cosmos-uc-davis` vs `cosmos-uc-santa-cruz` |
| Different tracks under one umbrella → same group | Stony Brook courses + format tiers → `stony-brook-precollege` |
| Format variants → same group | Stanford AI4ALL residential + online → `stanford-ai4all` |
| Stable across years | Keep the same slug when refreshing annually unless the program structurally changes |

Slug format: lowercase letters, numbers, hyphens; no spaces. Max ~60 characters.

## Search result grouping

Decisions locked for UI implementation:

| Behavior | Rule |
|---|---|
| Result count | Count distinct **Program Group ID** values, not rows |
| When to collapse | Group when **2+ offerings** from the same group match filters |
| Single match | One matching row in a group → render as a normal card (no expand) |
| Default state | Collapsed; expand to see variant sub-rows |
| Save | Always per offering (`id`), never per group |
| Saved indicator | Collapsed card may show "Saved 2 of 8 options" (among matching variants) |
| Sort | Sort groups by best-matching variant (cheapest, earliest start, etc.) |

## Row-splitting guide

Use this when migrating from 2026 or researching new programs.

| Situation | Action |
|---|---|
| Multiple sessions with different dates | One row per session |
| Residential vs Commuter vs Online | One row per format (when price or dates differ) |
| Multiple tracks/courses | One row per track |
| Same session, same format, same dates, same price | One row (use **Offering Label** for track if needed) |
| CMU-style "Residential $10,744; Commuter $8,253" on one row | Split into two rows with respective prices |
| Stony Brook course + "See pricing above" | Split: format-tier rows with real prices + one row per course inheriting/copying the relevant price |
| COSMOS campus with many clusters listed in track | Keep one row per campus (clusters are chooser options, not separate offerings) unless a cluster has distinct dates/price |

## Validation rules (import)

The 2027 import script should **reject or flag** rows that fail these checks:

### Errors (block import)

- Missing required column or empty required field
- **Format** not exactly `Residential`, `Commuter`, or `Online`
- **Grade Completed Min** > **Grade Completed Max**
- **Date Start** > **Date End**
- **Date Start/End** missing when **Dates Parse Quality** is `exact` or `approximate`
- **Price Min** > **Price Max**
- **Program Group ID** or **URL** empty
- Cross-reference phrases in any field: `see above`, `see pricing`, `choose session`, `varies by track`
- Semicolon-separated dates in **Dates Display** (sign of unsplit sessions)
- Slash-separated formats: `Residential/Commuter`, `Residential/Online`

### Warnings (import but log)

- **Price Min/Max** empty but **Price Display** is not `Contact program`
- **Length Min/Max Days** empty when **Length Display** suggests a fixed duration
- **State** empty for a US residential/commuter program
- **Description** empty
- Duplicate slug (same group + offering label + format + date start)
- **Review Status** is `verified` but **Data Verified At** is empty
- **Season Year** does not match **Date Start** year (when dates are `exact`)

### Import behavior by review status

| Review Status | Import action |
|---|---|
| `verified` | Include in seed |
| `provisional` | Include in seed; set `reviewStatus` for UI badge |
| `awaiting_source` | Include or exclude per publish policy (default: include with badge) |
| `needs_review` | **Exclude** from seed; log row count in validation report |

## Gotcha flags

Unchanged from 2026:

- Maintained in `data/seed/flags.json`
- Matched at import by **Program Group ID** (preferred) or program name pattern
- Each flag requires `sourceCitation` and optional `sourceDate`
- See [DATA.md — Gotcha flags](./DATA.md#gotcha-flags-curated-layer)

**2027 change:** update flag matchers to use `programGroupId` where possible (e.g. `cosmos-*` → all COSMOS campus groups).
